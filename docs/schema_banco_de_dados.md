## Autoincremento — GENERATED BY DEFAULT AS IDENTITY

Todas as colunas `id` utilizam o recurso nativo do PostgreSQL 10+:

```sql
id INTEGER GENERATED BY DEFAULT AS IDENTITY
```

Isso é equivalente ao antigo `SERIAL`, porém padronizado pelo SQL (ISO/IEC 9075) e com vantagens:

| Característica | `SERIAL` (legado) | `IDENTITY` (atual) |
|----------------|-------------------|--------------------|
| Padrão SQL | Não | Sim (SQL:2003) |
| Sequência interna | Exposta (`tablename_id_seq`) | Gerenciada internamente |
| Permite INSERT explícito | Sim | Sim (`BY DEFAULT`) |
| Suporte no SQLAlchemy 2.x | Via `autoincrement=True` | Via `Identity(always=False)` |

O modo `always=False` (`BY DEFAULT`) foi escolhido para permitir inserções com `id` explícito em migrações e testes.

### Migração automática

A função `_migrar_identity()` em `inicializacao_banco.py` converte instalações existentes (que usavam `SERIAL`) para `IDENTITY` de forma idempotente:

1. Detecta se a coluna já é `IDENTITY` → pula
2. Se ainda é `SERIAL` (default `nextval(...)`) → remove o default, adiciona `IDENTITY` com `START WITH <max_id + 1>`, descarta a sequência órfã
3. Ignora dialetos não-PostgreSQL (SQLite, etc.)

## Tabelas

### 1. `usuarios`

Autenticação e controle de acesso à plataforma. Sem FK para outras tabelas.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `nome` | `VARCHAR(120)` | NOT NULL | Nome completo do usuário |
| `email` | `VARCHAR(180)` | NOT NULL · UNIQUE · índice | Login e identificação |
| `senha_hash` | `VARCHAR(255)` | NOT NULL | Hash bcrypt da senha |
| `perfil` | `VARCHAR(30)` | NOT NULL · default `analista_esg` | Papel no sistema: `administrador`, `gerente_esg`, `analista_esg`, `operador_esg`, `cientista_dados` |
| `ativo` | `BOOLEAN` | NOT NULL · default `true` | Conta habilitada |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data de criação (UTC) |

**Índices:** `id` (PK), `email` (unique)

| `governance_score` | `INTEGER` | NOT NULL | Score de governança (0–1000) |

| `email` | `VARCHAR(180)` | NULL | E-mail de contato |

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |

| `name` | `VARCHAR(220)` | NOT NULL · índice | Razão social (desnormalizado) |
| `industry` | `VARCHAR(100)` | NOT NULL | Setor (desnormalizado) |
| `environment_score` | `INTEGER` | NOT NULL | Score ambiental de entrada (0–1000) |
| `social_score` | `INTEGER` | NOT NULL | Score social de entrada (0–1000) |
| `governance_score` | `INTEGER` | NOT NULL | Score de governança de entrada (0–1000) |
| `total_score` | `INTEGER` | NOT NULL | Soma bruta dos três scores |
| `score_ponderado` | `FLOAT` | NOT NULL | Score ponderado pelos pesos do setor (0–1000) |
| `grade` | `VARCHAR(10)` | NOT NULL | Conceito (ex.: `A`, `B+`) |
| `level` | `VARCHAR(40)` | NOT NULL | Nível textual (ex.: `Avançado`) |

**Índices:** `id` (PK), `fornecedor_id`, `name`

---

### 4. `planos_acao`

Itens estruturados do plano de ação ESG por avaliação. Cada avaliação pode ter múltiplos itens (um por pilar que precisa de atenção). `fornecedor_id` é um atalho direto para consultas sem JOIN com a avaliação.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `avaliacao_id` | `INTEGER` | FK · NOT NULL · CASCADE · índice | Avaliação pai (`avaliacoes_esg.id`) |
| `fornecedor_id` | `INTEGER` | FK · NULL · SET NULL · índice | Atalho para `fornecedores.id` |
| `pilar` | `VARCHAR(5)` | NOT NULL | `E` (ambiental), `S` (social) ou `G` (governança) |
| `score` | `INTEGER` | NOT NULL | Score do pilar na avaliação (0–1000) |
| `importancia` | `FLOAT` | NOT NULL | Feature importance do Random Forest para o pilar |
| `acao` | `TEXT` | NOT NULL | Texto da ação recomendada |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data de criação (UTC) |

**Índices:** `id` (PK), `avaliacao_id`, `fornecedor_id`
**Cascade:** excluir uma `avaliacoes_esg` remove todos os seus `planos_acao` em cascata.

---

### 5. `experimentos_ml`

Rastreamento de execuções de treinamento ML. Sem FK para outras tabelas. Criado a cada execução de `treinar_modelo.py` ou `POST /treinar`.

| Coluna | Tipo SQL | Restrições | Descrição |
|--------|----------|------------|-----------|
| `id` | `INTEGER` | PK · IDENTITY | Identificador único autoincremento |
| `nome_execucao` | `VARCHAR(120)` | NOT NULL | Nome da run (ex.: `treino_20250615_143022`) |
| `knn_acuracia` | `FLOAT` | default `0` | Acurácia do KNN no conjunto de teste |
| `knn_f1_medium` | `FLOAT` | default `0` | F1-Score (classe Medium) do KNN |
| `knn_precision` | `FLOAT` | NULL | Precisão macro do KNN |
| `knn_recall` | `FLOAT` | NULL | Recall macro do KNN |
| `rf_acuracia` | `FLOAT` | default `0` | Acurácia do Random Forest no conjunto de teste |
| `rf_f1_medium` | `FLOAT` | default `0` | F1-Score (classe Medium) do RF |
| `rf_precision` | `FLOAT` | NULL | Precisão macro do RF |
| `rf_recall` | `FLOAT` | NULL | Recall macro do RF |
| `knn_params` | `TEXT` | NULL | Hiperparâmetros GridSearchCV do KNN (serializado) |
| `rf_params` | `TEXT` | NULL | Hiperparâmetros GridSearchCV do RF (serializado) |
| `mlflow_run_id` | `VARCHAR(120)` | NULL | ID da run no MLflow |
| `criado_em` | `TIMESTAMPTZ` | default `now()` | Data e hora do treinamento (UTC) |

> **Nota de migração:** `knn_precision`, `knn_recall`, `rf_precision` e `rf_recall` foram adicionadas via `ALTER TABLE`. Registros anteriores têm `NULL` nessas colunas.

## Relacionamentos

| Tabela origem | Coluna | Tabela destino | Coluna | Cardinalidade | On Delete |
|---------------|--------|----------------|--------|---------------|-----------|
| `avaliacoes_esg` | `fornecedor_id` | `fornecedores` | `id` | N → 1 | SET NULL |
| `planos_acao` | `avaliacao_id` | `avaliacoes_esg` | `id` | N → 1 | CASCADE |
| `planos_acao` | `fornecedor_id` | `fornecedores` | `id` | N → 1 | SET NULL |

**Tabelas isoladas** (sem FK): `usuarios`, `experimentos_ml`

---

## Comportamento de deleção

| Cenário | Efeito |
|---------|--------|
| Excluir `fornecedores` | `avaliacoes_esg.fornecedor_id` → `NULL` · `planos_acao.fornecedor_id` → `NULL` |
| Excluir `avaliacoes_esg` | `planos_acao` vinculados são **removidos em cascata** |
| Excluir `usuarios` | Nenhum efeito em outras tabelas |
| Excluir `experimentos_ml` | Nenhum efeito em outras tabelas |

## Views

### `vw_fornecedores_classificacoes`

Lista cada fornecedor com sua **classificação ESG mais recente** e todos os itens do plano de ação correspondente.

- Retorna **uma linha por item de plano de ação** (ou uma linha sem plano quando o fornecedor ainda não foi avaliado)
- A avaliação mais recente é selecionada via `LATERAL JOIN` com `ORDER BY criado_em DESC LIMIT 1`
- Criada/atualizada automaticamente via `CREATE OR REPLACE VIEW` no startup da API e ao rodar `inicializar_banco.py`

**Colunas expostas:**

| Coluna | Origem | Descrição |
|--------|--------|-----------|
| `fornecedor_id` | `fornecedores.id` | ID do fornecedor |
| `razao_social` | `fornecedores.name` | Nome do fornecedor |
| `setor` | `fornecedores.industry` | Setor em inglês |
| `cnpj` | `fornecedores.cnpj` | CNPJ |
| `environment_score` | `fornecedores` | Score ambiental (0–1000) |
| `social_score` | `fornecedores` | Score social (0–1000) |
| `governance_score` | `fornecedores` | Score de governança (0–1000) |
| `fornecedor_criado_em` | `fornecedores.criado_em` | Data de cadastro do fornecedor |
| `avaliacao_id` | `avaliacoes_esg.id` | ID da última avaliação |
| `total_score` | `avaliacoes_esg` | Score total bruto |
| `score_ponderado` | `avaliacoes_esg` | Score ponderado (0–1000) |
| `pontuacao_esg` | calculado | Score na escala 0–100 (`score_ponderado / 10`) |
| `grade` | `avaliacoes_esg` | Conceito (ex.: `A`) |
| `level` | `avaliacoes_esg` | Nível textual |
| `risco` | `avaliacoes_esg` | Índice de risco (0–100) |
| `impacto` | `avaliacoes_esg` | Índice de impacto (0–100) |
| `quadrante` | `avaliacoes_esg` | Quadrante risco × impacto |
| `maturidade_rf` | `avaliacoes_esg` | Maturidade pelo Random Forest |
| `confianca_rf_high` | `avaliacoes_esg` | Confiança RF para `High` (%) |
| `maturidade_knn` | `avaliacoes_esg` | Maturidade pelo KNN |
| `confianca_knn_high` | `avaliacoes_esg` | Confiança KNN para `High` (%) |
| `w_e / w_s / w_g` | `avaliacoes_esg` | Pesos ESG aplicados |
| `fonte_pesos` | `avaliacoes_esg` | Origem dos pesos |
| `avaliacao_criado_em` | `avaliacoes_esg.criado_em` | Data da avaliação |
| `plano_id` | `planos_acao.id` | ID do item do plano |
| `pilar` | `planos_acao` | Pilar: `E`, `S` ou `G` |
| `pilar_score` | `planos_acao.score` | Score do pilar (0–1000) |
| `importancia` | `planos_acao` | Feature importance RF |
| `acao` | `planos_acao` | Texto da ação recomendada |

**Exemplos de uso:**

```sql
-- Todos os fornecedores com classificação e plano de ação
SELECT * FROM vw_fornecedores_classificacoes;

-- Apenas fornecedores de alto risco (score < 500)
SELECT DISTINCT fornecedor_id, razao_social, pontuacao_esg, risco
FROM vw_fornecedores_classificacoes
WHERE risco > 60
ORDER BY risco DESC;

-- Plano de ação completo de um fornecedor
SELECT pilar, pilar_score, importancia, acao
FROM vw_fornecedores_classificacoes
WHERE razao_social = 'Fornecedor Exemplo LTDA'
ORDER BY importancia DESC;

-- Resumo por setor
SELECT setor, COUNT(DISTINCT fornecedor_id) AS total,
       ROUND(AVG(pontuacao_esg)::numeric, 1)  AS score_medio
FROM vw_fornecedores_classificacoes
GROUP BY setor
ORDER BY score_medio DESC;
```

## Dashboard Estatístico — Consultas SQL

Endpoint: `GET /dashboard/estatistico`  
Arquivo backend: `esg_ml/interfaces/api/rotas_enterprise.py` — função `dashboard_estatistico()` (linha ≈ 851)  
Arquivo frontend: `frontend/frontend/app.py` — função `render_dashboard_estatistico()`  
Cliente API: `frontend/frontend/cliente_api.py` — método `dashboard_estatistico()`

O endpoint aceita 4 parâmetros opcionais de filtro via query string:

| Parâmetro | Tipo | Exemplo | Efeito |
|-----------|------|---------|--------|
| `data_inicio` | `YYYY-MM-DD` | `2025-01-01` | `criado_em >= data_inicio` |
| `data_fim` | `YYYY-MM-DD` | `2025-12-31` | `criado_em <= data_fim 23:59:59` |
| `setor` | `string` | `Technology` | `industry = setor` |
| `maturidade` | `string` | `High` | `maturidade_rf = maturidade` |

Os filtros são compostos com `AND` quando mais de um é informado. Todas as queries abaixo assumem que os filtros opcionais podem ser acrescentados na cláusula `WHERE`.

### Q-1 · Setores disponíveis (filtro dinâmico do frontend)

**Usado em:** `sessao.query(AvaliacaoBanco.industry).distinct().all()`  
**Propósito:** Popular o selectbox "Setor" na tela do dashboard sem depender de tabela de domínio.  
**Saída da API:** campo `setores_disponiveis` (sempre retornado sem filtro de setor).

```sql
SELECT DISTINCT industry AS setor
FROM   avaliacoes_esg
ORDER  BY industry;
```

---

### Q-2 · Query principal — avaliações com filtros

**Usado em:** `sessao.query(AvaliacaoBanco)` com `.filter()` encadeados  
**Propósito:** Base de dados carregada em memória (DataFrame pandas) que alimenta todos os cálculos subsequentes.  
**Saída da API:** campo `registros_detalhe` (subconjunto das colunas, para box plot e tabela detalhada).

```sql
SELECT *
FROM   avaliacoes_esg
WHERE  criado_em   >= :data_inicio    -- se informado
  AND  criado_em   <= :data_fim       -- se informado  (+ ' 23:59:59')
  AND  industry     = :setor          -- se informado
  AND  maturidade_rf = :maturidade;  -- se informado
```

**Colunas derivadas calculadas em Python** (após o SELECT, não enviadas ao banco):

```sql
-- Nível de risco  →  _nivel_risco() em rotas_enterprise.py linha ≈ 100
CASE
    WHEN risco > 60 THEN 'alto'
    WHEN risco > 30 THEN 'medio'
    ELSE                 'baixo'
END AS nivel_risco,

-- Scores convertidos para escala 0–100
ROUND((score_ponderado  / 10.0)::NUMERIC, 2) AS pontuacao_esg,
ROUND((environment_score/ 10.0)::NUMERIC, 2) AS ambiental,
ROUND((social_score     / 10.0)::NUMERIC, 2) AS social,
ROUND((governance_score / 10.0)::NUMERIC, 2) AS governanca,

-- Período mensal para série temporal
TO_CHAR(criado_em, 'YYYY-MM') AS periodo
```

### Q-3 · KPIs resumidos

**Usado em:** bloco `kpis = {...}` da função `dashboard_estatistico()`  
**Propósito:** Alimentar os 5 cards de indicadores no topo da tela.  
**Saída da API:** campo `kpis`.

```sql
SELECT
    COUNT(*)                                                          AS total_avaliacoes,
    COUNT(DISTINCT fornecedor_id)                                     AS total_fornecedores,
    COUNT(DISTINCT industry)                                          AS total_setores,
    ROUND(AVG(score_ponderado / 10.0)::NUMERIC, 2)                   AS score_medio,
    ROUND(AVG(risco)::NUMERIC, 2)                                     AS risco_medio,
    ROUND(
        100.0 * SUM(CASE WHEN risco > 60 THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1
    )                                                                 AS percentual_alto_risco,
    ROUND(
        100.0 * SUM(CASE WHEN maturidade_rf = 'High' THEN 1 ELSE 0 END)
              / NULLIF(COUNT(*), 0), 1
    )                                                                 AS percentual_maturidade_high
FROM avaliacoes_esg
[WHERE <filtros>];
```

### Q-4 · Estatísticas descritivas por pilar (tabela + Gráficos 1 e 4)

**Usado em:** função `_stats()` interna, chamada para cada variável  
**Propósito:** Preencher a tabela de estatísticas descritivas e os gráficos:
- **Gráfico 1** (box plot) — mediana, Q1, Q3, outliers
- **Gráfico 4** (radar) — comparativo média × mediana  
**Saída da API:** campo `estatisticas` com subchaves `ambiental`, `social`, `governanca`, `total_esg`, `risco`.

```sql
-- Executado para cada variável: ambiental, social, governança, score ESG ponderado, risco
-- Exemplo para pilar Ambiental (environment_score / 10.0)

SELECT
    AVG(environment_score / 10.0)                                         AS media,
    PERCENTILE_CONT(0.5)  WITHIN GROUP (ORDER BY environment_score / 10.0)
                                                                          AS mediana,
    MODE()                WITHIN GROUP (ORDER BY
        ROUND((environment_score / 10.0)::NUMERIC, 2))                   AS moda,
    VAR_SAMP(environment_score / 10.0)                                    AS variancia,
    STDDEV_SAMP(environment_score / 10.0)                                 AS desvio_padrao,
    MIN(environment_score / 10.0)                                         AS minimo,
    MAX(environment_score / 10.0)                                         AS maximo,
    PERCENTILE_CONT(0.25) WITHIN GROUP (ORDER BY environment_score / 10.0) AS q1,
    PERCENTILE_CONT(0.75) WITHIN GROUP (ORDER BY environment_score / 10.0) AS q3,
    COUNT(*)                                                               AS total
FROM avaliacoes_esg
[WHERE <filtros>];

-- Repetir substituindo a expressão por:
--   social_score      / 10.0   →  Social
--   governance_score  / 10.0   →  Governança
--   score_ponderado   / 10.0   →  Score ESG Ponderado
--   risco                      →  Risco
```

> **Implementação:** pandas usa `.mean()`, `.median()`, `.mode()`, `.var()`, `.std()`, `.min()`, `.max()`, `.quantile(0.25/0.75)`. O equivalente SQL padrão PostgreSQL usa `AVG`, `PERCENTILE_CONT`, `MODE()`, `VAR_SAMP`, `STDDEV_SAMP`, `MIN`, `MAX`.

### Q-10 · Matriz de correlação de Pearson (Gráfico 7 — heatmap)

**Usado em:** `df[cols].corr()` — pandas calcula correlação de Pearson entre pares de variáveis  
**Propósito:** Gráfico 7 — heatmap mostrando o coeficiente de correlação (−1 a +1) entre as variáveis ESG, risco e impacto.  
**Saída da API:** campo `correlacoes` com subchaves `labels` (lista de variáveis) e `matrix` (matriz 6×6).

```sql
-- Variáveis: Ambiental, Social, Governança, Score ESG, Risco, Impacto
-- PostgreSQL calcula correlação de Pearson com a função CORR(y, x)

SELECT
    -- Correlações com Ambiental
    CORR(environment_score/10.0, social_score/10.0)     AS corr_amb_social,
    CORR(environment_score/10.0, governance_score/10.0) AS corr_amb_gov,
    CORR(environment_score/10.0, score_ponderado/10.0)  AS corr_amb_esg,
    CORR(environment_score/10.0, risco)                  AS corr_amb_risco,
    CORR(environment_score/10.0, impacto)                AS corr_amb_impacto,

    -- Correlações com Social
    CORR(social_score/10.0, governance_score/10.0)      AS corr_social_gov,
    CORR(social_score/10.0, score_ponderado/10.0)       AS corr_social_esg,
    CORR(social_score/10.0, risco)                       AS corr_social_risco,
    CORR(social_score/10.0, impacto)                     AS corr_social_impacto,

    -- Correlações com Governança
    CORR(governance_score/10.0, score_ponderado/10.0)   AS corr_gov_esg,
    CORR(governance_score/10.0, risco)                   AS corr_gov_risco,
    CORR(governance_score/10.0, impacto)                 AS corr_gov_impacto,

    -- Correlações com Score ESG
    CORR(score_ponderado/10.0, risco)                    AS corr_esg_risco,
    CORR(score_ponderado/10.0, impacto)                  AS corr_esg_impacto,

    -- Correlação Risco × Impacto
    CORR(risco, impacto)                                 AS corr_risco_impacto
FROM avaliacoes_esg
[WHERE <filtros>];
```

> **Nota:** A diagonal principal da matriz sempre vale `1.0` (variável correlacionada consigo mesma). A matriz é simétrica: `corr(A, B) = corr(B, A)`.

### Tabela `log_importacoes_fornecedores`

Registra cada evento de importação/criação de fornecedor no sistema, identificando o usuário responsável e agrupando registros do mesmo lote.

### Stored Procedure `sp_registrar_importacao`

Inserção segura na tabela de log de importações. Chamada explicitamente pelo código Python após cada persistência bem-sucedida de fornecedor.

```sql
CREATE OR REPLACE PROCEDURE sp_registrar_importacao(
    p_fornecedor_id INTEGER,
    p_razao_social  VARCHAR,
    p_cnpj          VARCHAR,
    p_usuario_id    INTEGER,
    p_usuario_email VARCHAR,
```

### Função de Trigger `fn_audit_fornecedores` e Trigger `trg_audit_fornecedores`

```sql
CREATE OR REPLACE FUNCTION fn_audit_fornecedores()
RETURNS TRIGGER
LANGUAGE plpgsql
AS $$
BEGIN
    IF TG_OP = 'INSERT' THEN
        INSERT INTO log_alteracoes_fornecedores
            (fornecedor_id, operacao, dados_novos, usuario_bd)
        VALUES (NEW.id, 'INSERT', row_to_json(NEW)::TEXT, current_user);
        RETURN NEW;
    ELSIF TG_OP = 'UPDATE' THEN
        INSERT INTO log_alteracoes_fornecedores
            (fornecedor_id, operacao, dados_anteriores, dados_novos, usuario_bd)
        VALUES (OLD.id, 'UPDATE', row_to_json(OLD)::TEXT, row_to_json(NEW)::TEXT, current_user);
        RETURN NEW;
    ELSIF TG_OP = 'DELETE' THEN
        INSERT INTO log_alteracoes_fornecedores
            (fornecedor_id, operacao, dados_anteriores, usuario_bd)
        VALUES (OLD.id, 'DELETE', row_to_json(OLD)::TEXT, current_user);
        RETURN OLD;
    END IF;
    RETURN NULL;
END;
$$;

-- Dispara APÓS INSERT, UPDATE ou DELETE (uma linha por operação)
CREATE TRIGGER trg_audit_fornecedores
AFTER INSERT OR UPDATE OR DELETE ON fornecedores
FOR EACH ROW EXECUTE FUNCTION fn_audit_fornecedores();
```

A função e o trigger são criados/recriados no startup da API via `_criar_log_alteracoes_fornecedores()` em `esg_ml/infraestrutura/inicializacao_banco.py`.

**Fluxo de auditoria:**
```
Aplicação Python
    │  sessao.add(FornecedorBanco(...))
    │  sessao.flush()
    ▼
PostgreSQL: INSERT INTO fornecedores ...
    │
    ▼  (trigger automático)
PostgreSQL: INSERT INTO log_alteracoes_fornecedores
            (fornecedor_id=<id>, operacao='INSERT',
             dados_novos='{"id":1,"name":"Acme",...}',
             usuario_bd='neondb_user')
```

```sql
-- Importações dos últimos 7 dias por usuário
SELECT usuario_email, operacao, COUNT(*) AS total, DATE(data_hora) AS dia
```

## Convenções

- Todas as PKs usam `INTEGER GENERATED BY DEFAULT AS IDENTITY` (PostgreSQL nativo, sem dependência de sequências externas).
- Todos os timestamps usam `TIMESTAMPTZ` (com fuso horário), armazenados em UTC.
- Scores ESG seguem a escala **0–1000** no banco; a conversão para 0–100 é feita na camada da API ou via coluna calculada `pontuacao_esg` na view.
- O campo `industry` armazena o valor em inglês no padrão do dataset Kaggle (ex.: `Technology`, `Healthcare`); a conversão PT → EN ocorre na rota `POST /classificar`.
- Tabelas de log (`log_*`) são append-only e não devem ser modificadas diretamente pelo código da aplicação — use sempre a stored procedure ou aguarde o trigger.
